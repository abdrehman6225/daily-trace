ACE-RL trains one model to act, reflect and write its own playbook

Why read · It is a working recipe for training an agent's memory-writing with RL instead of hand-tuning it, and it scores each written note by what it does to the next attempt.

Doyoung Kim, Byeongguk Jeon, Kailin Zhang, Sherry Yang — KAIST AI

NYU and KAIST AI (Sherry Yang's group) start from a gap between two methods. Outcome-only RL squeezes a whole trial, error logs included, into one scalar. Harnesses like ACE (Agentic Context Engineering) pass a text playbook from one attempt to the next, but the model writing that playbook is never trained. ACE-RL trains one model in three roles: actor, reflector (turns a trajectory into an insight) and curator (adds, updates or removes playbook tips). Each candidate playbook is scored by a fresh actor rollout under it, using the task verifier. An edit gets that score. A reflection gets the mean score of the edits made from it. Each role is normalized GRPO-style against its own comparison group: reflections of the same trajectory, edits of the same insight.

At equal compute, best-of-3 sequential attempts (RSI@3) reach 0.775, 0.987, 0.667 and 0.340 on Mastermind, MBPP, AppWorld and MiniSWEBench. GRPO's best of 3 independent tries (pass@3) gets 0.686, 0.867, 0.624 and 0.245. Delayed-joint PPO gives every role the chain's shared reward through a critic, and it collapses to near zero on AppWorld. Limits: only 0.6B and 4B Qwen3 models were tested, each method was trained once, and playbooks are per-task only.

Under the hood

  • Budget matches GRPO's 8 actor rollouts per task: 4 seed rollouts plus up to 4 that score candidate playbooks (M=2 reflections, C=3 edits).
  • The playbook kept for the next round is the best-scoring candidate if it beats the seed's reward. It resets every 3 encounters. Edits that change nothing earn 0.
  • Trained to 3 attempts, it still beats GRPO pass@K at K=8: AppWorld 0.81 vs 0.68, MiniSWEBench 0.40 vs 0.30.
  • Discarding edits isolates the playbook's own gain: +0.105 on AppWorld at K=2. On Mastermind the gain fades after K=3.

Takeaway. If agents write memory for later runs, score each memory write by a fresh rollout that uses it, and compare it only with other writes from the same input. Don't spread one end-of-chain reward over every step. Also check whether an actor-only RL model actually gets better inside your harness. Here, after 8 attempts it did worse than 8 independent samples.

Learn · today's concept

GRPO: group-relative advantages without a critic

Policy-gradient RL needs a baseline. You push up outputs that did better than expected and push down outputs that did worse. PPO gets its 'expected' value from a learned value network, called the critic. For LLMs the critic is about as large as the policy, so it costs a lot of memory and compute. It is also hard to train when the only reward comes at the end of a long output. Group Relative Policy Optimization (GRPO), introduced in DeepSeekMath, drops the critic. Its baseline is the other samples drawn for the same prompt.

Step by step: for one prompt, sample a group of G outputs from the current policy. Score each one with a reward, such as a verifier, a unit test, or (in ACE-RL) a fresh rollout that uses the note the model wrote. Compute each output's advantage as (r_i − group mean) / group std, and give that same value to every token in output i. Then apply PPO's clipped ratio objective, usually with a KL penalty toward a reference model. Example: G = 4 with rewards 1, 0, 0, 1. The mean is 0.5 and the std is 0.5, so the advantages are +1, −1, −1, +1. If all four outputs score 1, every advantage is 0 and that prompt teaches nothing.

Trade-offs: there is no critic to train, and the baseline is fair because it only compares outputs that started from the same input. The costs are G samples per prompt and coarse credit, since every token in an output shares one number. That is why LEAD-RL adds per-agent gating. Dividing by the std gives very easy and very hard prompts extra weight, and averaging over each sequence's length can bias how long outputs get. Dr. GRPO removes both. Use GRPO when rewards can be checked automatically and sampling several outputs per prompt is affordable.

Further reading: DeepSeekMath: Pushing the Limits of Mathematical Reasoning in Open Language Models (Shao et al., 2024); Understanding R1-Zero-Like Training: A Critical Perspective (Liu et al., 2025), the Dr. GRPO paper

Raschka explains RoPE, partial RoPE and NoPE, with PyTorch code

Why read · A clear explanation, with code, of how attention knows token order, and why recent open models rotate only some dimensions or drop explicit positions entirely.

Sebastian Raschka starts from GPT-2, which adds one of 1,024 learned position vectors to each token embedding. In GPT-2 Medium that table is 0.30% of the weights, but at a 100k context it would be more than 22%. RoPE (Rotary Position Embedding, from the 2021 RoFormer paper) works differently. It rotates each query/key feature pair by an angle m*theta_i, with theta_i = 10000^(-2i/d), and leaves the value vectors alone. The q-k score then depends only on the gap between the two positions. His toy example: shifting both tokens by 3 keeps a pair's score at 13, while moving the key one position closer raises it to 19.92. The cos/sin tables (1024x64 for a head of 128 features) are computed once and shared across all heads. There are two ways to pair features, split-half and interleaved (used by RoFormer and LLaMA v1). They give the same result only if the feature order is permuted to match.

On current models: MiniMax-M3 uses partial RoPE, rotating 64 of each head's 128 dimensions. That saves 128 MiB of BF16 tables at a 1M context and leaves the KV cache the same size. Raschka thinks it is "hardly worth it." NoPE layers use no explicit position at all and rely on the causal mask, which only lets a token see earlier tokens. The fetched text cuts off partway through the NoPE section. The top HN comment describes positional embeddings as group representations, with RoPE as a representation of the translation group.

Under the hood

  • The causal mask alone leaks position. If attention is uniform, a feature that is 1 only on the first token averages to 1/prefix-length.
  • In the NoPE paper, a 107M-parameter decoder tested on inputs longer than it was trained on ranked first across ten tasks (copying, sorting, addition), ahead of RoPE.
  • The 'Fractional Rotation, Full Potential?' paper (1B-8B models): rotating about 10% of each head's features roughly matched full RoPE, but full RoPE won some evaluations.
  • A RoPE self-test: assert_close(scores, scores_shifted) after adding 3 to every position confirms the attention scores do not change.

Takeaway. If you port or load RoPE weights, check that the pairing convention (split-half or interleaved) matches the checkpoint. Use the shift-invariance assert as a cheap unit test for any attention code you write.

Interactive explainer: REINFORCE-style weight perturbation trains a four-neuron agent

Why read · An interactive explainer that shows gradient-free policy search as a path through a 3-parameter space, and how changing the reward produces different behaviors.

Aatish Bhatia (physicist turned science journalist) and neuroscientist Arkarup Banerjee build a Braitenberg-style "spark": two eye neurons and two flipper neurons, controlled by three numbers (straight weight, crossed weight, drive). Each trial adds random noise to the weights, runs 500 steps, and scores the run by mean brightness along the path. The update is ΔW = α·ε·(R − R̄), with a running-average reward as the baseline. Hundreds of random starts all converge on the same optimum. Change the reward and the same setup learns to flee, freeze or charge instead.

Under the hood

  • Motor model: v_L = ReLU(w_s·b_L + w_c·b_R + d), mirrored for v_R. Forward speed is the mean of the two flipper speeds; turning is proportional to their difference.
  • The method is a version of Williams' 1992 REINFORCE, with noise added to the weights rather than to neuron outputs (weight perturbation). This is close to the evolution strategies OpenAI used on Atari in 2017.
  • Milestones: moving after 50 trials, overshooting the light at 500, reliably following the light by 2,000. Some learners needed thousands of trials.
  • HN commenters liked the clarity but objected that the brain analogy is never marked as an analogy. One wanted the link to gradients made explicit.

Takeaway. Perturbing the weights and scaling the update by reward minus a running baseline is a simple gradient-free optimizer you can write in a few lines. The baseline is what keeps the noisy updates usable. The same loop also shows how much the reward definition alone decides what behavior you get.

AI agents translate the US income tax into Lean, then test it against three tax engines

Why read · A worked example of guarding agent-written code: an adversarial reviewer agent, published test cases and differential testing against independent implementations.

Lexifina used AI agents to translate the 2025 individual income tax into Lean, a language whose type checker can verify proofs. Translation was the error-prone step, so they checked it three ways: against IRS worked examples, with a second agent reviewing adversarially for code written to pass tests, and by comparing 5,000 households against PolicyEngine-US, Tax-Calculator and UsTaxes. Their model matched PolicyEngine on 4,993. The disagreements exposed 14 UsTaxes bugs and two in their own model. A separate checker found 138 drafting errors in the tax code. No lawyer or CPA has reviewed the results.

Under the hood

  • Lean proves the IRS Tax Table differs from the statutory formula by −$5 to +$6 for every income under $100,000 and every filing status.
  • Each of the 138 dead references, typos and unclosed parentheses comes with a Lean certificate. All 138 re-check in about 2.5 minutes, and git blame names the law that introduced each one.
  • HN: commenters point to Catala as prior art for formalizing law (used in a French government service) and note that judges rule on intent, not just the wording.

Takeaway. If an LLM translates a spec into code, check it with published examples, a separate reviewer agent and differential testing (comparing outputs) against independent implementations. Look hardest at cases where two other implementations agree with each other and not with yours.

uBlock Origin bug let any website add script-injecting filters with one click

Why read · A clear case study in an unauthenticated message channel across a trust boundary, which applies to any extension, iframe or agent tool surface.

uBlock Origin's element picker runs in an iframe at moz-extension://<uuid>/.../epicker-ui.html, and that iframe can tell the background script to add filters. A malicious page leaked the random per-install UUID by hooking XMLHttpRequest.open while a default no-fetch-if scriptlet fetched a bundled resource. It then embedded the picker invisibly, drove it over postMessage, and put a newline in the opt field to append a trusted +js(...) filter for any domain. One click let it run JavaScript on any site (universal XSS). It is fixed in 1.76.4 and uBO Lite 2026.1110.1816.

Under the hood

  • Root cause: the picker accepted epickerStart/showDialog/resultsetDetails messages from any embedder. The fix adds a secret that the real content script passes to the picker.
  • Filters added through the picker are treated as trusted until a recompile, so scriptlets like trusted-rpnt can rewrite scripts on any site.
  • The author says GPT-5.6 Sol found the bug and Claude wrote most of the proof-of-concept. HN commenters asked why the picker UI isn't in browser chrome instead of the page DOM.

Takeaway. Any privileged endpoint reachable through postMessage or an embeddable URL needs a shared secret or an origin check before it acts. Fields that get concatenated into a rule language must reject delimiters like newlines.

Old Bitly short links reissued to strangers and repointed in 2011-era tweets

Why read · A real case of identifier reuse: a deleted short code was handed to someone new, and every old reference to it followed.

Old tweets from Burger King, McDonald's and Trump were not hacked. Their Bitly back-halves (the code after bit.ly/) were registered again on 14–15 November 2026 and pointed at new pages, even though Bitly's help pages say back-halves "cannot be re-used". Ransomnews checked 97 bit.ly links in Trump's 2009–2013 tweets using Bitly's + info page. 56 had been re-created after the tweet, 48 of them in a 17-minute run in May 2023. 7 now led elsewhere and 1 was blocked. Bitly confirmed the issue, suspended the accounts involved and began disabling the links. Disruptionist reported in February 2025 that Bitly had fixed a similar bug.

Under the hood

  • How to check: add + to a bit.ly link to see its destination and creation date. If the date is later than the post, the code was reissued. Ransomnews tested this on links with known dates first.
  • Bitly deletes accounts after 3 years of inactivity. The 2025 bug let anyone claim a back-half once its link or account was deleted, and the 2026 creation dates show the same was possible again.
  • References can break twice: two replaced Trump links point to domains that copy crypto-service names, and both domains were re-registered after the links were created.
  • HN: one commenter sees the same pattern with DNS. University subdomains whose CNAME records point at lapsed domains are taken over when spammers buy those domains.

Takeaway. Never reissue a public identifier (short code, username, subdomain, object key) after it is deleted; keep it permanently reserved. Use short domains you own, and regularly check outbound links and CNAME targets for ownership changes.

vLLM serves Inkling 2 Small with a fused all-reduce and a custom decode kernel

Why read · A new architecture feature added new serving costs, and the post shows which kernels removed them, with numbers for long-context agent workloads.

Thinking Machines' Inkling 2 Small is a mixture-of-experts (MoE) model with 594B total and 17B active parameters: 48 layers, 384 experts, 8 active per token. It has 1M context and takes images as input. The main change from Inkling is block attention residuals, which replace the residual stream: before each sublayer, a learned query mixes the outputs of earlier 6-layer blocks. Attention also gets a sigmoid gate. Experts use NVFP4 in layers 0–39 and MXFP8 in layers 40–47, so one node can serve the model. A 5-layer DSpark draft model proposes 7 tokens per step. The launch post describes a single joint RL run: 1,075 steps, 17M+ rollouts, 9 days on 2,048 GPUs.

Attention residuals turn every sublayer boundary into five memory-bound steps: all-reduce, short convolution, residual update, mix and RMSNorm. vLLM fuses all five into one allreduce_conv_mix kernel over NVLink multicast. During prefill, sequence parallelism has each GPU handle only its own slice of tokens, which cuts an 8K prefill step by 22% at TP4 and 26% at TP8. The 6:1 query-to-KV head ratio silently turned off FlashAttention-4's head packing. A custom Gluon decode kernel brought batch-1 decode at 100K context from 15.1 ms to 4.8 ms. On an agent workload at TP8 with every user at 100 tok/s, output per GPU is about 1,070 tok/s at 32K context and about 450 tok/s at 256K.

Under the hood

  • Four Over Six NVFP4: for each 16-element block, the quantizer scales the block maximum to both 6 and 4 and keeps whichever gives lower reconstruction error.
  • Gluon kernel: one warp streams KV through TMA, one runs tcgen05 MMAs, four apply softmax with relative bias. The 6 query heads share one 64-row tile, so KV is read once.
  • Activation quantization happens inside the routing and SwiGLU kernels, with no separate pass. Kernels launch with PDL (programmatic dependent launch), so each one's setup overlaps the end of the previous kernel.
  • Prefix-cache hit rate is 91% at 32K and 99% at 256K, with acceptance length 3.3–3.5. One user at TP4 decodes at about 630 tok/s.

Takeaway. Before adopting a new residual or attention variant, count the memory-bound ops it adds at each layer boundary and check whether fused kernels can absorb them. Also check that your head ratios don't silently switch off your attention kernel's fast path.

vLLM on Vera Rubin NVL72: DeepSeek-V4.1-Flash at 58× GB300 throughput

Why read · The most reusable part is not the kernels. It is a rack-wide shared prefix cache that lets requests go to any rank instead of staying pinned to one session's rank.

vLLM and Inferact report serving DeepSeek-V4.1-Flash on one Vera Rubin NVL72 rack at 1.7M tokens/s per GPU while each user gets 387 tokens/s. They say that is 58× GB300 NVL72 on the SemiAnalysis AgentX agentic benchmark. Kernels were rebuilt for Rubin's two memory domains per GPU and new FP4 instructions: prefill steps are about 28% faster and decode steps about 25%. The most transferable change is cache pooling. Prefix KV moved into one Mooncake store across the rack, so Dynamo routes each request to the least-loaded rank. At 4,800 concurrent sessions, median time to first token fell from 29.8 s to 4.2 s.

Under the hood

  • Pooling plus routing served 68% more requests and raised the prefix hit rate from 91.8% to 96.1%. Async out-of-process lookups cut steps waiting on KV loads from 13.5% to 1%.
  • Engram's two 94.4 GiB n-gram tables are now split 10.5 GiB across 18 prefill GPUs and read over NVLink. This frees host DRAM for about 1,500 more sessions.
  • TP8 across two trays costs only 0.3 µs extra per all-reduce. With speculative-decode acceptance fixed at 3.51 tokens/step, single-user speed rose from 1,117 to 1,844 tokens/s at P50.

Takeaway. Pinning each session to one rank keeps its cache warm but leaves some ranks idle while others queue. With a shared prefix store, moving a request costs a cache load instead of a recompute, so plain least-loaded routing can balance the ranks.

NVIDIA Developer · 1 min

Serving the 753B GLM-5.3 split across two GB300 DGX Stations with vLLM

Why read · A multi-node recipe for a MoE model too big for one GPU, with concurrency numbers that show where throughput stops scaling.

NVIDIA's NVFP4 build of GLM-5.3 (753B parameters, 40B active per token) is about 464 GB, more than the 252 GB on one GB300. The tutorial splits it across two DGX Stations with tensor parallelism (each GPU holds half of every weight matrix, ~218 GiB each), linked by a 400 Gb/s RoCE (RDMA over Ethernet) link, using vLLM v0.30.0. On SPEED-Bench Coding prompts, total throughput peaks at 607.8 tok/s at concurrency 16 and drops to 385.0 tok/s at 32, where mean latency reaches 453.5 s. Per-user speed falls from 115.3 to 13.0 tok/s.

Under the hood

  • Launch flags: multi-token prediction drafting 4 tokens per step (a form of speculative decoding), FP8 KV cache, prefix caching, 98,304-token context, 0.93 GPU memory utilization, max-num-seqs 16.
  • Uses NCCL 2.30.7 because older versions can deadlock cross-node CUDA graph replays over RoCE (vLLM issue #52504). It also checks the NCCL logs to confirm GPUDirect RDMA is used, not a fall back to TCP sockets.
  • HN comments: about 7-year payback on roughly $100K per Station versus $1.4/M hosted output tokens; one user reports 60% more throughput from 8× RTX Pro 6000 at about half the cost; each Station draws 1.6 kW.

Takeaway. With tensor parallelism across two nodes, every token waits on the network link, so measure the concurrency where total throughput peaks (here 16) and cap the server's batch size there. Also confirm in the NCCL logs that traffic uses RDMA, not TCP.

IBM's LLMON markup separates instructions from data using reserved tokens, in Granite 4.1

Why read · If your agents take in retrieved documents or tool output, LLMON marks every part of the prompt with its own address so the model only acts on the instruction it is told to run.

IBM released two experimental models, granite-4.1-3b-LLMON-preview and granite-4.1-8b-LLMON-preview, trained on LLMON. It is an XML-like markup whose six delimiters are reserved single tokens, so its structure can't be confused with ordinary text the way JSON's quotes and braces can. Each part of a prompt (instruction, data, requirement) becomes a block with a two-token ID. An exec block then says which instruction runs on which data. The model learns to ignore blocks the exec block doesn't point to, but this is not guaranteed. On the OPI prompt-injection benchmark it blocks 47% more attacks than the best frontier model tested. Its general benchmark scores match Granite 4.1 Instruct.

Under the hood

  • Training started from the base checkpoints. An instruct corpus was rewritten as LLMON, with decoy blocks added that the exec block never references and that leave the target output unchanged.
  • After that: five GRPO stages (reasoning, RLHF, knowledge calibration, math), then DPO on about 1,000 on-policy pairs built from the model's own answers to injection attempts.
  • You can define your own tags. On ScienceWorld they trained a LoRA with tags like data.state.inventory and assistant.next_action. The tests cover static injections only; attacks spread over many turns are still being worked on.

Takeaway. Give each piece of the context an ID, and state explicitly which instruction applies to which data. This works even without LLMON. A model only treats unreferenced text as passive if it was trained with unbound decoys, as LLMON was.

Hugging Face · 1 min

llama.cpp and ggml reach v1.0.0 and adopt semantic versioning

Why read · If you ship anything that links libllama or libggml, breaking changes to the C API will now show up as major-version bumps.

The ggml-org team at Hugging Face released libllama and libggml v1.0.0, 3.5 years after the project began. From now on, any API or ABI break in the public C headers under include/ will bump the major version. Minor bumps cover new features, backend updates, model support and API additions. Patch bumps are bug fixes with no API change. The post gives no benchmarks. It says llama.cpp supports more than 150 architecture variants and all mainstream speculative decoding methods, and that each backend can be built as a dynamic library and loaded at runtime.

Under the hood

  • The semver promise covers the public headers only: llama.cpp/include/ for libllama and ggml/include/ for libggml.
  • Distribution channels: pre-release artifacts for Linux, macOS, Windows, Android and iOS, plus Docker, Debian, Homebrew, conda-forge, MacPorts, Winget and an XCFramework for iOS and macOS.
  • CI runs on HF Buckets and HF Jobs, with self-hosted runners on hardware from NVIDIA, AMD, Qualcomm, Arm, IBM and Intel.

Takeaway. If you wrap libllama, for example in a Go or Python binding, pin it to a major version now and treat any major bump as an ABI break. Anything outside include/ still carries no stability promise.

Meta Engineering · 1 min

Meta ports Android's Cuttlefish emulator to run natively on Apple silicon

Why read · A short case study in removing Linux-only assumptions from a VMM stack. It also shows how emulated devices give agents isolated test environments that can be reset.

Meta Reality Labs had been running two Android emulators side by side. Goldfish runs everywhere but is less faithful to real hardware. Cuttlefish, AOSP's virtual-device framework, boots real system images but only runs on Linux. To merge them, Meta brought back Cuttlefish's dormant QEMU backend and removed its Linux-only assumptions. That meant letting vhost-user (device backends that run as separate processes and talk to QEMU over a socket) build on macOS, raising HVF's memory-slot limit and adding a native Cocoa display. The QEMU work ships as the qemu-wearables fork and the Cuttlefish changes as the cuttlefish-wearables patch set.

Under the hood

  • QEMU's vhost-user frontends, libvhost-user and contrib backends such as vhost-user-blk could only build on Linux; Meta removed those build restrictions so they build on macOS too.
  • QEMU's HVF backend (Hypervisor.framework, Apple's equivalent of KVM) did not track enough memory regions for large Cuttlefish configurations, so Meta raised its tracking-slot count.
  • The native Cocoa display gained BGRA pixel format support, mouse clicks translated into touch input and a -g geometry flag. It also needed the macOS JIT entitlement and code signing/notarization.

Takeaway. Before porting a VMM stack off Linux, look for compile-time gates and hard-coded hypervisor limits first, since that is where Meta found the breaks. Running developers and CI on the same virtual device gives agents reproducible environments that can be reset with snapshots.

Tencent's LoopForge runs coding-agent CLIs through fixed workflows with approval steps

Why read · It is an MIT-licensed Go harness that coordinates Claude Code, Codex and eight other agent CLIs, with checks and human sign-off built into each run.

LoopForge is a self-hosted platform from Tencent. It does not replace coding agents. It runs ten existing agent CLIs, including CodeBuddy, Codex, Claude Code and DeepSeek Harness, inside Docker sandboxes. Its unit of work is an SOP, a reusable workflow made of Agent, Script, Human-gate and sub-SOP nodes. Each node declares what it depends on, and a step starts once those finish. A failed check or a rejection can send the work back to an earlier step. Roles such as planning, implementation and review each have their own prompt, model and MCP tools, so the code is never reviewed by the agent that wrote it.

Under the hood

  • Setup: ./start.sh pulls a pinned GHCR image and starts MySQL plus the platform on port 8090. Agent runs are logged and resumable, and token cost is tracked per requirement.
  • Sandboxes start through the host Docker socket, which gives control of the host daemon, so the project says it is for trusted teams, not multi-tenant isolation.
  • npx loopforge-cli install claude adds the built-in workflows to Claude Code, Codex, Cursor and others without running a server.

Takeaway. If you build agent harnesses, the useful idea is to mix deterministic script steps and human gates with agent steps, and let a failed check send work back to an earlier step. That beats trusting a single agent run.

Tailscale's tailcat: WireGuard peer-to-peer tunnels without Tailscale's control plane

Why read · It shows how a NAT-traversing encrypted tunnel can work with no coordination server, and it is a Go library you can embed in your own services.

Tailscale open-sourced tailcat, a Go library and CLI that works like netcat (the classic tool for piping raw data over a network connection). It runs over Tailscale's data plane but skips the control plane, so it needs no account and no root. The data plane is magicsock: userspace WireGuard, NAT hole-punching that finds peer addresses with STUN, and DERP, Tailscale's encrypted relay. The server prints a tc... address, about 140 bytes of base64 CBOR. It holds the WireGuard public key, a separate path-discovery key, a 256-bit pre-shared key and a DERP region. The client sends a "Meow" through DERP. The server adds it as a WireGuard peer, then traffic moves to direct UDP when hole-punching succeeds. gVisor's userspace TCP/IP stack handles TCP inside the process.

Under the hood

  • The address works like a password because it contains the pre-shared key. If you publish it in a DNS TXT record, also use --allow=nodekey:... or --ssh-authorized-keys. Before connecting to a DNS name, tailcat ssh tries to log in with a fresh stranger key and refuses if that succeeds.
  • Built-in services: port forwarding, exit node, SOCKS5, SSH, inetd-style exec, SFTP limited to one directory via Go's os.Root, and an iperf-style perf test that refuses to run over shared DERP relays.
  • UDP payloads are capped at 1232 bytes (MaxUDPPayload) so they fit the IPv6 tunnel MTU. Idle server UDP flows close after 2 minutes. The Go API, CLI and wire format have no stability promise.

Takeaway. Keeping rendezvous separate from the data path means a self-contained capability string, shared out of band, can replace a coordination service. If you need agents or dev machines to reach each other behind NAT, tailcat.Server and tailcat.Client give you this in a few lines of Go, and you can run your own DERP relay.

LEAD-RL: per-subagent credit gating for jointly trained research swarms

Why read · If you train a main agent and its subagents together, this is a simple fix for misassigned credit, and it also made trajectories cheaper without any cost reward.

In multi-agent deep research, a main agent sends briefs to parallel subagents. Each subagent works in its own isolated context and returns only a condensed report. Training both roles jointly creates a credit problem: if every subagent inherits the rollout's group-relative advantage, misleading reports get rewarded in successful runs and useful ones get punished in failed runs. LEAD-RL comes from the authors of WebClipper and SlimSearcher. It keeps final-answer correctness as the only reward. A training-only judge (DeepSeek V4 Pro) labels each report helpful, neutral or harmful using the brief, the report, the reference answer and the subagent's own tool outputs. The judge never sees the team outcome. Helpful reports keep only positive advantage (max(A,0)), harmful reports keep only negative advantage (min(A,0)), and neutral reports keep A. The main agent always receives the raw team advantage.

On BrowseComp, a 124B-A5.1B Ling-based model reaches 73.49%. That is 2.49 points above shared team credit, with critical-path cost (main-agent steps plus the longest subagent branch at each delegation) down 24.5%, from 323.3 to 244.2 steps. Main-only RL and shared-credit RL both scored below their SFT starting point. Caveats: the same model judges both training and evals, and the authors say the efficiency mechanism is a hypothesis they did not measure.

Under the hood

  • Shared policy for both roles, trained with sample-level GSPO: K=4 rollouts per question, 32 questions per update, up to 16 subagents per rollout, KL coefficient 0.001.
  • Subagent advantage is divided by the number of trainable subagents and scaled by w(t), annealed from 0.4 to 0.2, so spawning more branches cannot inflate the update.
  • Judge labels below 0.8 confidence become neutral, and a harmful label requires a materially misleading claim. A failed or incomplete search counts as neutral, not harmful.
  • With the swarm on, the trained model rose from 58.0% to 73.5% at roughly flat tokens (331k→337k per question). It sits 1.8 points behind the 1.6T-A49B DeepSeek V4 Pro and beats the 284B-A13B DeepSeek V4 Flash.

Takeaway. When a team outcome drives per-agent RL updates, use a cheap per-unit judgment to gate the sign of the advantage each unit inherits, and keep the single scalar reward. In the authors' tests this cut wasted subagent work without any cost penalty.

DeepStress feeds search agents bad documents on purpose to test robustness

Why read · A method for honest evals of retrieval agents: control how good the evidence is, score cautious answers separately, and check how much comes from the model's own memory.

Ismael Rousseau, Geraldine Damnati, Frederic Bechet — Orange

DeepStress, from Orange Research and Aix-Marseille, replaces an agent's search tool with Gemma-4-31B. For each query it writes one document whose trustworthiness, relevance and factuality are set at a chosen rate. The authors ran 12 systems on HotpotQA and BrowseComp-Plus, 33,600 traces in total. RL-trained Search-R1 stayed at 78–80% correct even when sources came from fake-news domains. GPT-5 variants instead abstained or used up their tool budget. With every document false, HotpotQA still reached up to 60% correct from the model's own memory, while BrowseComp-Plus fell to near zero.

Under the hood

  • RAS (reliability-aware score): correct = 1, wrong or malformed = 0. Abstaining or running out of tool budget earns 1−ρ, where ρ is the product of the realized trust, relevance and factuality rates. CoPRAS is cost divided by RAS.
  • At 0% document quality, mean correctness is 0.30 and mean RAS is 0.61. Average cost rises from 10.9k to 20.5k, and GPT-5-nano (medium) costs 3.5× more.
  • Relevant but false documents hurt more than irrelevant ones: DR-Tulu gives 59.1% wrong answers at 0% factuality versus 33.8% at 0% relevance.

Takeaway. When you evaluate a retrieval or memory agent, feed it bad evidence at controlled rates and count abstentions separately from wrong answers. Always add a no-retrieval baseline so answers recalled from the model's own memory don't pass as good retrieval.

A tiny router on hidden states decides whether an LLM should reason at all

Why read · If you build agents, this cuts reasoning tokens by up to 80%, and the RL recipe learns when to think from episode returns alone, with no per-step labels.

Zhengxu Yu, Ke Xu, Meng Fang, Haitham Ammar, Weilin Luo, Jun Wang

Huawei Noah's Ark, Liverpool and UCL keep a Qwen backbone frozen and give it two modes. In the fast mode it answers from one forward pass by reading the logits of the candidate answers, with no tokens generated. In the slow mode it writes a full chain of thought. A block of a few hundred kilobytes reads the final hidden state and eight output statistics. It predicts all four right/wrong combinations for the two modes and escalates when log(P(slow right)/P(fast right)) exceeds a price λ set per request. For agent tasks, CDPO trains the block with PPO on the episode's return, discounted for each escalation.

Under the hood

  • Escalation reuses the fast pass's prefill through SGLang's prefix cache. Only one routing decision is made per question, and thinking is capped at 4,096 tokens.
  • Qwen3.8-27B: reaching 90% of always-think accuracy costs 103 tokens per question, against 112 for RouteLLM, 138 for a confidence threshold and 591 for always thinking. On MiniWoB it gives up 0.05 reward for 80.1% fewer tokens.
  • The hidden state carries the routing signal: AUROC is 0.778 with it and 0.671 with output statistics alone. On BANKING77, thinking hurts: 0.913 with it against 0.923 for the fast mode.

Takeaway. Route on whether thinking would change the answer, not on how confident the model is. You can train that router as a four-way classifier by running both modes over labelled data, then pick the cost at request time with a threshold.

Loopback: looped Transformers that store per-block updates and reweight them with decay plus attention

Why read · Looped Transformers reuse the same blocks several times. This paper treats the residual stream as memory across depth and shows that choosing what to store and how to read it back changes quality.

Xuan Ouyang, Zefan Cai, Chenlong Zhang, Cheng Luo, Ke Wan, Junjie Hu — University of Wisconsin - Madison

A group at UW–Madison, working with UCSB, Caltech and Microsoft, proposes Loopback, a new way to combine residuals in looped Transformers (models that apply one shared stack of blocks several times). Most designs store each block's full output. Loopback stores only the change each block makes, δ = f(x) − x, and keeps the loop's original input on its own path with a fixed weight of 1. A geometric decay (λ per iteration) sets the total weight given to updates. A softmax reader with no projections then shares that weight out by content. On the ClimbMix pretraining corpus, at 191M to 3B, Loopback gets lower validation loss than standard Transformers of the same depth while using 40–75% of their Transformer parameters.

Under the hood

  • Ablation at 191M/374M: removing decay adds 0.043/0.034 nats of loss, while removing attention adds only 0.003/0.003.
  • At inference with 8 loop visits, 191M loss rises 0.060 for Loopback against 0.454 for a plain loop. At 1.4B with 4 visits: 0.028 against 0.248.
  • Costs 0.04–0.08% extra FLOPs and 6% lower training throughput at 3B on 8 H100s. The update history grows as O(KRd) per token. Large-scale results are single runs on one corpus.

Takeaway. When a memory gets repeated writes, store the deltas rather than snapshots, and set the total weight separately from how it is split, here with a decay for the total and attention for the split. Snapshots tie earlier writes into every later weight, and plain summing lets the total grow with the number of steps.

Ant Group's UniSpark-9B uses hybrid linear and full attention for unified multimodal models

Why read · It shows how to keep scratch work out of a recurrent state that later steps reuse, and the same problem shows up in agent memory.

Jiancheng Pan, Yuzheng Liu, Hengyuan Cao, Qiyuan Zhang, Yangyan Li, Biao Gong, Zheng Zhang, Ka Long Cheng et al. — Ant Group

Ant Group's UniSpark-9B handles image understanding, generation, editing and interleaved text–image output in one model. It is built on Qwen3.5's mix of full attention and GatedDeltaNet layers (linear attention that keeps a fixed-size, decaying memory state), with separate understanding and generation experts of about 9B parameters each. The key rule is that noisy images still being denoised stay private, while finished images become shared context. Full-attention layers enforce this with block masks. Linear layers process a noisy block from the shared state, then throw those updates away. The model scores 2470.3 on MME-S and 0.83 on GenEval. The fetched text stops before the experiments section, so no baseline comparisons are available.

Under the hood

  • The linear-layer update rule is: a public block (text or a clean image) advances the shared state; a private block (a noisy image) leaves it unchanged. The two experts share the recurrent state and short-convolution history.
  • Training data: 159.7M generation samples, 213.4M understanding samples (10.0M OCR, 4.5M grounding), 97.9M text-only samples and 624.8K interleaved sequences. A four-stage curriculum takes generation from 256 resolution to 2K.
  • Packing: full attention masks across sample boundaries, and linear layers reset their state and conv history at each boundary. Training used AdamW at LR 1e-4 with FSDP hybrid sharding and a frozen Wan2.2 VAE.

Takeaway. If you mix recurrent state with attention, make a rule for which steps may write to the shared state. Let tentative work branch off a copy of the state, and write back only results you have committed to.
